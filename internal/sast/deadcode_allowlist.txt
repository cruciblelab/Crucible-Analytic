# Functions that no path reaches, and why each is allowed to stay.
#
# Format: <package path>.<func>  # reason
#
# One line per entry, and the reason is the point. An unexplained name
# teaches the next reader that this file is a place to silence things,
# and then it becomes one.
#
# # Why this file exists
#
# Two purge functions - PurgeOldLoginAttempts and PurgeOldDevAccess -
# were written, documented, correct, and called from nowhere. The tables
# they bounded had been growing without limit since the day they were
# created, and every test passed the whole time. Operation.LinkAudit was
# a third: panel_operations.audit_id was null on every row because the
# audit write returned no id for anyone to pass it.
#
# None of them failed. That is the whole problem: code that is never
# reached cannot fail, so nothing goes red and nobody finds out. A scan
# is the only thing that asks the question, and a scan nobody runs is
# the same as no scan - so it runs in CI, against this list.
#
# # What to do when the gate goes red
#
# Three honest answers, in order of preference:
#
#   1. Wire it. If it should be called, the gate has found a bug - that
#      is what happened to all three above.
#   2. Delete it. If it is a leftover, it is worse than absent: a reader
#      who believes in it writes code that assumes it runs.
#   3. Add it here with the reason. For something genuinely built ahead
#      of the surface that will use it, name the phase.
#
# What is not an answer is adding the name with no reason.
#
# # The fourth state: "unseen:"
#
# A line beginning `unseen:` means the function is still unreached and
# the scanner can no longer tell. deadcode works by rapid type analysis,
# and RTA stops judging a type the moment that type is stored in an
# interface - every method it has becomes something a dynamic call might
# reach.
#
# MOD1 did exactly that on purpose: internal/panel/web now hands
# *panel.Store to the narrow interfaces in stores.go, so that each area
# of the panel sees only the three or four methods it uses. The price,
# measured rather than guessed, was this file going from four entries to
# one. The three that went quiet were not wired up by anybody. The
# question simply stopped being answerable.
#
# Deleting them would have recorded "these got used", which is false, and
# would have thrown away the reasons written beside them. So they keep
# their reasons, and they are still checked - in the one direction that
# is left. An unseen entry must stay unseen: if it turns up in the report
# again the analysis has got its sight back, the gate goes red, and the
# decision gets made afresh instead of inherited.
